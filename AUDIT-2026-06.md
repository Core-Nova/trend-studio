# TREND Hair Boutique Studio — Site Audit (2026-06)

This audit inventories the current state of the trend-studio site across five lenses: SEO, analytics, design, UI/UX, and frontend code health. Findings are grounded in a full read of the repo on `main` at branch tip `698b8c3`. The output is a **prioritized fix list**, not a code change — implementation happens in follow-up PRs.

> Conventions: ✅ in place / working, ⚠️ partial or risk, ❌ missing.

---

## 1. SEO — strong foundation, small gaps

### In place

- **Static `<head>`** — full title/description, og:*, twitter:*, canonical, hreflang en/bg/x-default, viewport, theme-color in `index.html`.
- **Structured data** — JSON-LD `HairSalon` schema in `index.html` with `openingHoursSpecification`, `address`, `geo`, `aggregateRating` (5.0★, 45 reviews), `availableLanguage`, `makesOffer`, reservation action.
- **Per-route dynamic meta** — `src/hooks/usePageSEO.js` updates `document.title`, og/twitter title/description, canonical, og:url. Used by all 5 pages (`HomePage`, `GalleryPage`, `ServicesPage`, `AboutPage`, `ContactPage`).
- **`public/robots.txt`** with `Allow: /` and sitemap declaration.
- **`public/sitemap.xml`** — all 5 routes with `lastmod`, `changefreq`, `priority`.
- **Favicons** — 16/32/48/512px + apple-touch-icon.
- **Image alts** — `ALTS` array in [src/data/imageImports.js](src/data/imageImports.js) mapped 1:1 to all hero + gallery images. Descriptive ("Hair styling result at TREND Hair Boutique Studio Sofia").
- **Lazy loading** — gallery images use `loading="lazy"` from index 6 onward; first 6 eager.
- **Bilingual `seo.*` strings** in [src/translations/index.js](src/translations/index.js) lines 111–150 for all 5 page titles/descriptions.
- **`<html lang>` switching** — `LanguageContext` sets `document.documentElement.lang` per user selection.
- **Heading hierarchy** — sample scan: `h1` Hero title + sr-only "TREND", `h2` `SectionHeader` per section, `h3` per card. Clean.

### Gaps

- ❌ No `manifest.json` (PWA/installability, also flagged by Lighthouse).
- ⚠️ hreflang `en` / `bg` / `x-default` all point to `https://trendbytedi.com/` — language is client-side localStorage, not URL-based. Per-route hreflang isn't meaningful until URLs reflect language.
- ⚠️ `sitemap.xml` `lastmod` is manual — drifts with content updates.

## 2. Analytics — wired but uninstrumented

### In place

- **GA4 plumbing** — [src/lib/analytics.js](src/lib/analytics.js) exports `initAnalytics`, `trackPageView`, `trackEvent`. Loads gtag.js dynamically on init. `send_page_view: false` so SPA navigation is hand-rolled.
- **Page view tracking** — `trackPageView(location.pathname)` fires on every route change via `useLocation()` in [src/App.jsx:23](src/App.jsx).
- **Init lifecycle** — `initAnalytics()` runs once in `AppShell` `useEffect` ([src/App.jsx:50](src/App.jsx)).

### Gaps

- ⚠️ **Hardcoded fallback measurement ID** — [src/lib/analytics.js:8](src/lib/analytics.js): `'G-MEJCZTPTG5'`. When `VITE_GA_MEASUREMENT_ID` is unset (forks, dev branches, accidental missing env), production still ships hits to this property. The file's own comment says "so local dev and forks don't send hits by default" — the fallback contradicts that.
- ❌ **Zero event tracking** on every interactive surface:
  - `BookingButton` ([src/components/atoms/BookingButton.jsx](src/components/atoms/BookingButton.jsx)) — primary conversion, no `trackEvent`.
  - `tel:` phone link in [NavigationView.jsx:75](src/components/Navigation/NavigationView.jsx), `FooterView`, `StoriesViewer` — no tracking.
  - Instagram links in [NavigationView.jsx:81](src/components/Navigation/NavigationView.jsx), Footer, Gallery, Stories — no tracking.
  - EN/BG language toggle ([NavigationView.jsx:93–101](src/components/Navigation/NavigationView.jsx)) — no tracking.
  - Stories open/close/advance — no tracking.
  - Gallery image taps — no tracking.
  - Contact form (if any) — no tracking.
- ❌ **No consent UI** — no GDPR/cookie banner. Bulgaria ∈ EU; gtag runs unconditionally on page load.
- ❌ **No Consent Mode v2** — no `gtag('consent', 'default', { ... })` block before the gtag library loads.

## 3. Design — mature system, minor regressions to watch

### In place

- **Design tokens** at `:root` in [src/index.css:5-25](src/index.css):
  - Colors: `--gold-primary`, `--gold-light`, `--gold-dark`, `--burgundy`, `--cream`, `--black`, `--charcoal`, `--gray`, `--gray-light`.
  - Fonts: `--font-display` (Cormorant Garamond), `--font-script` (Great Vibes), `--font-body` (Montserrat).
  - Effects: `--shadow`, `--shadow-gold`.
- **Responsive typography** via `clamp()` — hero title `clamp(3rem, 10vw, 7rem)` ([index.css:372](src/index.css)), section titles `clamp(2.5rem, 5vw, 3.5rem)` ([index.css:547](src/index.css)).
- **Spacing scale** — section padding 100/70px desktop/mobile, container 20px, gaps 16/24/30/50.
- **Brand palette** consistently applied via CSS variables.
- **Bilingual stable buttons** — `BookingButton` uses `btn--stable` overlap grid so EN/BG width swap doesn't reflow.
- **`SectionHeader` atom** templates section title/tag/ornament across 9+ sections.

### Gaps

- None at the system level. The risk is regression: any new hardcoded `#hex`, fixed `px` font size, or unscoped font family undoes the consistency. The `lens-design` memory + `/trend-design-pass` skill exist to catch these going forward.

### In place

- **Skip link** ([NavigationView.jsx:10](src/components/Navigation/NavigationView.jsx), styled in [index.css:74-91](src/index.css)).
- **`:focus-visible` outline** — 2px gold, [index.css:57-61](src/index.css).
- **`prefers-reduced-motion` block** — [index.css:2841-2852](src/index.css).
- **ARIA**:
  - Menu button: `aria-label="Toggle menu"` + `aria-expanded` ([NavigationView.jsx:20-21](src/components/Navigation/NavigationView.jsx)).
  - Logo link: `aria-label` ([NavigationView.jsx:12](src/components/Navigation/NavigationView.jsx)).
  - Phone link: `aria-label` ([NavigationView.jsx:75](src/components/Navigation/NavigationView.jsx)).
  - Instagram link: `aria-label` ([NavigationView.jsx:85](src/components/Navigation/NavigationView.jsx)).
  - Stories viewer: `role="dialog"`, `aria-modal="true"`, `aria-label` on tap zones.
  - Current page: `aria-current="page"` on active nav link ([NavigationView.jsx:52](src/components/Navigation/NavigationView.jsx)).
- **Image alts** — `ResponsiveImage` propagates `alt` to `<img>`.
- **Responsive breakpoints** — 1600/1200/992/768/480.
- **Sticky mobile booking bar** ([index.css:1800-1803](src/index.css)).

### Gaps

- ❌ **EN/BG language toggle buttons** ([NavigationView.jsx:61-69, 93-101](src/components/Navigation/NavigationView.jsx)) lack `aria-label` and `aria-pressed`. Screen readers hear "EN" / "BG" with no role state.
- ⚠️ **Loading state** — Suspense fallback is a logo spinner ([App.jsx:30](src/App.jsx)), not a content-shaped skeleton. Acceptable, but skeletons feel faster on slow connections.
- ⚠️ **Color contrast** — not measured. Pale gold (`--gold-light` #C4A24E) on cream (`--cream` #F5ECD7) small text is the high-risk pairing for WCAG AA (4.5:1). Needs an axe/Lighthouse pass.

## 5. Frontend — clean, two named risks

### In place

- **Stack** — React 19.2, react-router-dom 7.13, Vite 7.2 — all current.
- **Route lazy-loading** — [src/App.jsx:12-16](src/App.jsx) `React.lazy()`s all non-Home pages.
- **Container/presenter split** — e.g. `Hero` wraps `HeroView`, `Gallery` wraps `GalleryView`, `Navigation` wraps `NavigationView`. Easy to test view layer.
- **Custom hook architecture** — 20+ hooks under `src/hooks/`. Logic out of components.
- **Effect cleanup** is consistent in `useIsMobile`, `useCarousel`, `useScrollReveal`, `useStories`, `useSlider` (uses mounted-flag for async unmount safety).
- **Image pipeline** — `vite-imagetools` + `vite-plugin-image-optimizer` (quality 80), AVIF + WebP srcsets generated at build.
- **CDN scripts** — three.js, BAS, TweenMax injected on `requestIdleCallback` ([index.html:34-55](index.html)), non-blocking.
- **State** — pure Context + local hooks (`LanguageContext` + `localStorage`). No global state lib needed.
- **Linting** — ESLint 9 + react-hooks + Prettier; `.prettierrc` single-quotes, no-semis, 100-col.

### Gaps

- ❌ **No ErrorBoundary** at the root. A render error in any section crashes the whole route tree to a white screen.
- ⚠️ **Hardcoded GA fallback ID** — repeats the analytics finding from §2, classified as a frontend hygiene issue too.
- ⚠️ **Memoization is sparse** — only `useGalleryImages`, `useStories`, carousel hooks use `useMemo`/`useCallback`. Acceptable for current scale; revisit if perf instrumentation says otherwise.
- ⚠️ **JSDoc gaps** on tricky hooks — `useSlider` returns `{ ready, controls: RefObject<...> }`, `useStories` returns a state machine, `useHeroSliders` orchestrates 1-or-2 sliders. None have `@returns` JSDoc. Future edits risk shape drift.
- ⚠️ **Test coverage thin** — 4 test files (`SectionHeader.test.jsx`, `useIsMobile.test.js`, `useStories.test.js`, `setup.js`) for ~3.7k LOC. Riskiest under-tested logic is `useStories` state machine and `useSlider` ready-flag race.
- ℹ️ **No `manualChunks`** in [vite.config.js](vite.config.js). Vendor split is implicit; bundle is small enough today, but flag if a heavy lib lands.
- ℹ️ **Pure JavaScript** — no TypeScript. JSDoc is the documentation contract; minimal currently.
